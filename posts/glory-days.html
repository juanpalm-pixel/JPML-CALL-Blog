What exactly is an API?

An Application Programming Interface, or API, is essentially a service[cite: 1]. While we interact with apps through buttons and screens, an API allows a user to communicate with a service directly via code[cite: 1]. Think of it as the "Front Desk" or a "Bouncer" for a service[cite: 1]. You've likely used them today without realizing it; Google Maps provides maps and directions via API, while Spotify uses them for music streaming[cite: 1]. In the world of linguistics, the Abair platform uses APIs for voice synthesis and recognition[cite: 1].

Public vs. Private Interfaces

Not all APIs are open to everyone. Public APIs, like Spotify’s, act as creative tools that let developers build new apps using data like track "danceability" or "acousticness"[cite: 1]. Conversely, private APIs are used internally by companies like Amazon to allow different parts of their system to talk to each other securely without exposing sensitive functions to the public[cite: 1].

Designing a RESTful API

Most modern APIs follow "RESTful" principles, which involve four basic operations: POST (write new info), GET (retrieve info), PUT (edit info), and DELETE[cite: 1]. For example, if you use the Abair synthesis API to turn text into speech, you use a POST request because the audio file doesn't exist yet and must be created[cite: 1]. If you’re just checking your Spotify login details, you're using a GET request to view existing information[cite: 1].

The Three Pillars of an API Gateway

As systems grow complex, developers often use an API Gateway to centralize multiple APIs[cite: 1]. While a single API acts as a gateway to its own service, a true Gateway acts like an "address book" for many different APIs[cite: 1]. A well-designed Gateway rests on three pillars:

  • Gatekeeping: This involves security through API Keys and "Rate Limiting" to ensure no one abuses the service[cite: 1].
  • Observability: Developers use tools like Grafana to monitor traffic and identify bottlenecks or "bad actors"[cite: 1].
  • Documentation: This is the most vital pillar; if a developer can't understand how to use your service, nobody will use it[cite: 1].
